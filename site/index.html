A contract carried a hidden instruction to copy payroll data into the report. The agent was blocked, the attempt was logged and the workspace was flagged for review.

The problem

Agents are getting file access.Nobody can say what they touched.

Today an agent gets a folder or a drive token and full trust. When something goes wrong, whether it's a bug, a bad prompt or an instruction hidden in a document, there's no record of what it read, no clear view of what it changed and no clean way to undo it.

How it works

Every task gets its own workspace.You decide what comes back.

01

Fork on start

The agent works on an instant copy-on-write fork of your files. The originals don't change while it works.

tether createno data copied
02

Scoped access

Each agent gets its own rules for each task. Files it can't read don't show up at all, and a sub-agent can never get more access than its parent.

contracts/** readreports/** writesecrets/** none
03

Every action signed

Every read, write, delete and blocked attempt goes into an append-only log. Each entry is signed and chained to the last, so an edit or deletion is detected.

HMAC-SHA256hash-chainedtether verify
04

Review before merge

When the agent submits, you see the diff, the flags and everything it did. Approve it and it lands on disk as a new version. Low-risk changes can be approved automatically by policy.

approvediscardauto-approve reports/**
05

Roll back anything

Every state of your files is a version. Restore any of them in one click. A rollback adds a new version, so history is never erased.

tether rollback 3
Security model

Built the way a security team would build it.Deny by default, everywhere.

Least privilege

Access is denied unless a rule grants it. Forks get the intersection of every policy above them.

Guardrails

Writes containing private keys or API tokens are blocked. Read and write budgets stop an agent that goes wide.

Flags block merges

Off-task behavior flags the workspace. Nobody merges it without confirming they reviewed what happened.

No self-approval

An agent can never approve its own changes, and a sub-agent can't give itself auto-approval.

Scoped credentials

Each token opens exactly one workspace. Only its hash is stored, and it stops working when the workspace closes.

Conflict-safe merges

If someone edited the same file while the agent worked, the merge stops and shows you which files conflict.

Get started

Three commands.Then hand your agent the keys.

Track a folder

Your files stay where they are.

$ pip install git+https://github.com/caydenrgarrett/tether
$ tether init ./drive

Give an agent a workspace

Here, Claude Code over MCP.

$ WS=$(tether create --agent agent:claude --read 'contracts/**' --write 'reports/**')
$ claude mcp add tether -- tether mcp --workspace $WS

Review what it did

Approve, discard or roll back.

$ tether serve   # http://localhost:8700
